## Context

当前 `src/ui.cpp` 的 `DrawDashboard` 把控件按功能分组平铺(ABXY 在左、D-pad 在右),没有设备轮廓。本变更重写布局,使其映射 Yoobox Y1 实物:在 1620×1080 屏上画出正面轮廓与顶部轮廓,把每个控件放到对应物理位置。参考图(用户提供的正面/顶部照片,位于 `~/Downloads/`)仅作为绘制形状的参考,不进入代码库——轮廓全部用 SDL 矢量绘制。

现有可复用的绘制函数:`DrawGlowRect`、`DrawCyberGrid`、`DrawButtonBox`(发光边框+按下填充)、`DrawDPad`(四段十字)、`DrawStickGauge`(外圈+位置点+数值)、`DrawTriggerBar`(水平条)。字体/文本辅助 `RenderText`/`DrawCentered` 不变。手柄状态读取(`SDL_GameControllerGetButton/GetAxis`)、事件日志、无控制器 idle、ESC 退出均沿用 `gamepad-input-tester`,本变更不改这些行为,只改呈现。

## Goals / Non-Goals

**Goals:**
- 用矢量绘制设备正面轮廓 + 顶部轮廓,并把每个控件放到与实物对应的位置。
- 布局镜像实物:左 D-pad、中屏幕、右 ABXY;摇杆分别在其下方;顶部两端为 ZL/ZR 与 L/R。
- 保持现有输入读取、事件日志、idle、ESC、cyber-grid 风格。

**Non-Goals:**
- 不用照片作底图,不新增 `res/` 图片资产。
- 不做照片级写实(逼真材质/阴影/高光)——只需可识别的轮廓与位置正确。
- 不改 `app`/`font`/`main`/`CMakeLists`。
- 不改输入行为(仍逐帧读 `SDL_GameController` 状态)。

## Decisions

### 1. 双视图布局:顶部轮廓条 + 正面轮廓大图
纵向上分为三块:
- top ≈ 28..118:标题 + 控制器状态行(保留现 `DrawStatusLine`)。
- top ≈ 150..300:**顶部轮廓**——一条横向长条,两端各画左/右肩键区(`LT/ZL`+`L`, `RT/ZR`+`R`),中部为排线/开关示意。
- top ≈ 320..970:**正面轮廓**——设备主体圆角矩形,中央为屏幕(黑底圆角矩形),左右为控制区,底部为 Start/Select 与 L3/R3。
- 底部 y≈1000 起:`DrawLog`(事件日志条)。

- **Why**:设备正面占比最大、放大多数控件;顶部轮廓是窄条,适合放在正面之上,模拟"俯视翻起"的可读关系。
- **Alternative**:顶/正面并排两列——受 1080 高限制,正面会被压得很小,不利于看清控件。

### 2. 轮廓用"圆角矩形 + 顶点多边形"矢量绘制
新增一个圆角矩形辅助函数(`DrawRoundedRect`),用填充+描边近似圆角(外接矩形为圆角;用 `SDL_RenderFillRect` 叠角部圆,或直接绘描边路径)。主体轮廓用暗色填充(`SDL_Color` 接近 `C.bg` 的深灰)作剪影,再描发光边;屏幕用更深的黑色矩形。控件指示沿用现有风格(按下→magenta 发光填充),轮廓本体保持中性深色以免喧宾夺主。

- **Why**:不引入图片资产,保持 cyber-grid 风格,且缩放/清晰度可控。
- **Alternative**:把 jpg 拷入 `res/` 作为纹理(SDL_Texture)——照片带真实屏幕/按键影像,叠加指示会与照片冲突,且增加针对单机型的资产;被否决。见用户选择。

### 3. 正面控件定位(与实物对应)
把空间划分成"左侧控制区 / 中央屏幕 / 右侧控制区"。各控件以其中心坐标落在对应区域,物理关系如下:
- **D-pad**:屏幕左侧,居中于左区上部(十字中心约在屏幕左缘外测)。
- **左摇杆**:D-pad 正下方。
- **ABXY**:屏幕右侧,菱形四键居中于右区上部(相对 D-pad 镜像)。
- **右摇杆**:ABXY 正下方。
- **Start / Select**:底部,靠左摇杆内/外侧(Start 在左下,Select 在右下,与实物一致)。
- **L3 / R3**:底部,左右摇杆下方/内侧。
- 屏幕:中央大黑圆角矩形,位于左右控制区之间。

- **Why**:镜像实物照片;测试人员可直读"哪只手按了什么"。
- **Alternative**:保留功能分组网格(现状)——不反映物理布局,被否决。

### 4. 顶部肩键区:LT/RT 深度 + L/R 按压
顶部轮廓两端各画一个肩键块:外侧为模拟扳机(`TL/TR`),内侧为肩键(`L/R`)。SDL 映射:`TRIGGERLEFT/TRIGGERRIGHT` → `LT(ZL)/RT(ZR)`(深度用现有 `DrawTriggerBar` 逻辑,在顶部块内画水平条);`LEFTSHOULDER/RIGHTSHOULDER` → `L/R`(按下高亮)。

- **Why**:SDL 将模拟扳机与肩键分离为轴与按键,二者需分别呈现;顶部视图是展示二者的自然位置。
- **Alternative**:把 LT/RT 与 L/R 都画在正面——与实物(在顶边)不符,被否决。

### 5. 保留事件日志与状态行
`DrawLog`、`DrawStatusLine` 原样复用,仅在坐标上避让新的顶部/正面轮廓区域。

## Risks / Trade-offs

- **手绘轮廓缺乏写实细节** → 只保证"可识别轮廓 + 控件位置正确",这是本变更的可接受范围(用户已选矢量方案)。
- **1620×1080 高度紧张**(顶部条 + 正面 + 日志) → 正面轮廓控制在合理高宽比,日志压缩到 4~5 行并置于底部;必要时缩小屏幕区域。
- **圆角矩形非 SDL 原生** → 用填充/描边叠加近似;若视觉不理想可后续微调,不影响输入行为。
- **布局坐标硬编码** → 与现有不同分辨率但固定 1620×1080 的做法一致(项目本就为该分辨率硬编码)。

## Migration Plan

纯 UI 布局变更,替换 `src/ui.cpp` 的绘制实现(新增 `DrawRoundedRect`/`DrawTopOutline`/`DrawFrontOutline` 等,修改 `DrawDashboard`)。无数据迁移。回滚 = `git checkout` `src/ui.cpp`(及 `src/ui.h` 若签名变化)。
